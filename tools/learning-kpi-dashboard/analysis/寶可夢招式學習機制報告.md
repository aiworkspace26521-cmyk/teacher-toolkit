> 分析日期：2026-08-14
> 分析範圍：`learning-kpi-dashboard` 前端 `kpi-dashboard.html` + `pokemon-skill-tree.js` + `pokemon-gen2-9.js`，後端 `kpi-core.js` / `index.js`

## 0. 總覽：五種招式學習途徑

本系統中一隻寶可夢能學到的招式，共來自**五種途徑**，且它們彼此**獨立、可並存**：

| 途徑 | 來源機制 | 招式資料表 | 是否佔裝備格 | 可否升級 |
|---|---|---|---|---|
| 1. 技能樹（Skill Tree） | SP 兌換、階層解鎖 | `TYPE_BASED_MOVES` / `TYPE_SPEC_V2` / `ARCHETYPE_TEMPLATES` | 是（上限 6） | 可（消耗 SP） |
| 2. TM 學習器 | 商店 150 金幣購買→詠唱消耗 | `MOVE_DATABASE`（全圖鑑真實招） | 是（追加於裝備後） | 不可 |
| 3. 種族招式池（自然招） | 按種族/屬性自動生成 | `SPECIES_LEARNSET` / `TYPE_MOVE_POOL` / `UNIVERSAL_MOVES` | 僅在無裝備時自動填入 | 否 |
| 4. 專屬招式（SIGNATURE） | 等級 ≥36 自動送 | `SIGNATURE_MOVES` | 由自動配招邏輯帶出 | 否 |
| 5. 進化保留 | 進化只改 `baseName`/`evoStage` | — | 既有招式全數保留 | 依招式原途徑 |

核心架構：**事件溯源（event sourcing）**。所有招式學習都寫成事件（`MOVE_LEARN`、`MOVE_UPGRADE`、`MOVE_EQUIP`、`SKILL_RESET`、`SP_ALLOCATE`），前端 `kpi-dashboard.html` 與後端 `kpi-core.js` **各自對同一批事件重播**，產生一致的狀態快照。

## 1. 技能樹系統（主要學習途徑）

### 1.1 技能樹結構

- 每隻寶可夢有五棵樹：`atk`（物理）、`spa`（特攻）、`buf`（增益）、`dis`（妨礙）、`ult`（究極）。
- 階層門檻（SP 投入量）：`TIER_SP_THRESHOLD = {1:0, 2:5, 3:12, 4:20, 5:30}`（`pokemon-skill-tree.js:9-13`）。
- 每招等級上限：`MAX_MOVE_LEVEL = {1:10, 2:8, 3:5, 4:3, 5:3}`（`pokemon-skill-tree.js:15`）。

### 1.2 SP 的取得與計算

- SP 是**衍生值**，不直接存檔，每次重播重新計算（`kpi-dashboard.html:1275-1288`）：
  ```
  totalSpEarned = (currentLevel − initialLevel) × 5 + bonusSp
  skillPoints   = totalSpEarned − investedSp
  ```
- `investedSp` = 五棵樹 `skillTree[tree].sp` 之合。
- **進化額外 SP**：第 1 次進化（stage 0→1）+5，第 2 次（1→2）+10（`kpi-dashboard.html:1173-1184`，後端 `kpi-core.js:504-515` 同步）。

### 1.3 階層解鎖（受進化影響）

```
maxTreeTier = evoStage≥2 或 (evoStage≥1 且為最終型態) → 5
            : evoStage≥1                              → 4
            : 其他                                     → 3
```
（`kpi-dashboard.html:1290-1300`）
- 「最終型態」由 `EVO_HAS_FURTHER` / `EVO_CHAIN_MAP` 決定（8/7 條進化鏈，含 `EVO_STAGE_OVERRIDES` 的分歧進化）。
- 也就是說**未進化只能點到 T3**，這是把「招式深度」綁在「遊戲達成度」上的設計。

### 1.4 招式學習與升級

- 學習：`learnMoveInSkillTree`（`kpi-dashboard.html:9734` 一帶）— 檢查前置條件、扣 SP、寫入 `learnedMoves[name] = {level:1, learnedAt, tier}`。
- 升級：`upgradeMoveInSkillTree` — 每次 +1 SP，受 `MAX_MOVE_LEVEL` 與剩餘 SP 限制（`kpi-dashboard.html:9791`）。**TM 招式不可升級**（`:9792`）。
- 裝備：上限 **6 招**，超過時 toast「最多攜帶 6 招」（`kpi-dashboard.html:9655`）。

### 1.5 Variant（變體）決定招式組成

- `stablePersonality`（學生ID+寶可夢ID+名稱雜湊）穩定決定變體，避免刷新後招式亂跳。
- `selectVariant()` 依能力值傾向選「物理強攻型 / 特攻轟炸型 / 平衡型」等（`pokemon-skill-tree.js:2441` 一帶 `buildTreeFromVariant()`）。
- `TYPE_SPEC_V2` 涵蓋全部 18 種屬性（含幽靈/鋼/惡/岩石/蟲等稀有屬性，`pokemon-skill-tree.js:859-1211`），每種屬性都有五樹專屬招式庫。
- 無法用招式庫對應時才退回 `ARCHETYPE_TEMPLATES`（Lv1-5 定型模板）或 `generateSkillTree` 自動生成。
- `resolveT5ForTree()`（`pokemon-skill-tree.js:2238-2239`）用 `isRealMove()` 驗證節點招是否為 `MOVE_DATABASE` 真實招式。

## 2. TM 學習器系統

### 2.1 取得管道

- 商店道具 `tmUniversal`：**150 金幣 × 1**（`GAME-MANUAL VER6.2.md:660-663`）。
- **限第三遊戲階段**（「跨區挑戰」M4–M6、Lv.38~70）才可購買（`GAME-MANUAL VER6.2.md:959` 解鎖條件）。
- 購買會寫入庫存 `globalData.tms`。

### 2.2 學習流程

- `openTMLearn`（`kpi-dashboard.html:7703`）→ `renderTMMoveList`（`:7716`）→ `learnTMMove`（`:7761`）：
  1. 消耗 1 個萬能 TM；
  2. 列出 `MOVE_DATABASE` 全部真實招式（可依屬性/名稱過濾）；
  3. **每隻上限 4 招 TM**，超過錯誤（`:7767`）；
  4. 寫入 `globalData.pokemonTMs[pid]` 並鏡射到 `pkmn.tmMoves`（`:1409-1413`）。

### 2.3 事件溯源對應

- 後端重播解析序語法：
  - 取得：`TM學習器:(\S+)`（`kpi-core.js:403-404`）；
  - 消耗：`消耗(\d+)個TM學習器`（`kpi-core.js:419`）。
- 前端事件白名單含 TM 相關 note 字串，保證前端重播與後端一致（`kpi-dashboard.html:1024/1027`）。

### 2.4 對戰使用

- `createPlayerPokemon` 先裝「已裝備招」再**把 TM 招接在後面**（`kpi-dashboard.html:3079-3103`）。
- 實際進入對戰的招式上限仍為 6（`equippedMoves.slice(0,6)`，`:3085`）。

## 3. 種族招式池與自動配招

> 適用於：野外/道館/聯盟敵方寶可夢、以及**從未手動配裝**的玩家寶可夢。

### 3.1 資料表

- `SPECIES_LEARNSET`：手寫種族招式池（伊布系/御三家/傳說等，`kpi-dashboard.html:1741`）。
- Gen2–9 的物種則透過 `generateLearnset`（`kpi-dashboard.html:2735`）從 `TYPE_MOVE_POOL`（18 屬性池，`kpi-dashboard.html:1840`）自動生成。
- `UNIVERSAL_MOVES`：20 招通用招（撞擊/叫聲/抓/電光一閃/拍擊/瞪眼/搖尾巴/變硬/影子分身/替身/守住/睡覺/高速星星/覺醒力量/劈開/摔打/百萬噸重拳/泰山壓頂/捨身衝撞/絕對零度/大爆炸/玉石俱碎，`kpi-dashboard.html:1733`）。

### 3.2 自動選招演算法（`getPokemonMoveset`, `kpi-dashboard.html:2816`）

為 4 招：
1. 第 1、2 招：依「物攻高→物理招優先，特攻高→特攻招優先」從種族池挑最強；
2. 第 3 招：補**屬性覆蓋**（非重複屬性的招式）；
3. 第 4 招：威力最高，或 **等級 ≥36 時給專屬招**（`SIGNATURE_MOVES`：超夢→精神擊破、火焰鳥→神鳥猛擊、烈空坐→畫龍點睛、洛奇亞→氣旋攻擊、鳳王→神聖之火、帝牙盧卡→時光咆哮，`kpi-dashboard.html:1861`）。

### 3.3 敵方寶可夢

- `createEnemyPokemon`（`kpi-dashboard.html:3054-3077`）從該池**隨機抽最多 4 招**。
- 傳說敵方在 Lv≥36 時自動掛上專屬招。

## 4. 進化對招式的影響

- `doEvolve`（`kpi-dashboard.html:8227`）→ `EVO_STAGE_MAP` 更新 `baseName`（去掉括號系名）與 `evoStage`，並授予進化 SP 加給（+5/+10）。
- **進化不掉招**：`learnedMoves`、`equippedMoves`、`tmMoves`、`skillTree` SP 全部保留；只有「可點到的階層」（`maxTreeTier`）與技能樹「可學的招式」依新 `baseName` 重算。
- `doEeveeDirectEvolve`（`kpi-dashboard.html:8206`）：伊布用進化石直進化，招式保留、屬性標籤更新。

## 5. 各寶可夢的運作差異

| 種類 | 學習機制差異 |
|---|---|
| **御三家/一般系（Gen1）** | `SPECIES_LEARNSET` 手寫池 + `TYPE_SPEC_V2` 變體樹；自然進化兩段，最終型態才能開 T5 |
| **伊布系** | 7 條分歧進化鏈由 `EVO_STAGE_OVERRIDES` 維護；用石頭走 `doEeveeDirectEvolve`；各進化型各有獨立技能樹 |
| **Gen2–9 物種** | `generateLearnset` 由屬性池自動產招池；招式資料在 `frontend\pokemon-gen2-9.js` 的 `MOVE_DATABASE` |
| **傳說（超夢/火焰鳥等）** | 進化較早達最終型態（T5 提早開）；Lv≥36 由 `SIGNATURE_MOVES` 給專屬招 |
| **雙屬性** | `TYPE_BASED_MOVES` 混池（`pokemon-skill-tree.js:2020`）；技能樹以主屬性為準 |

## 6. 事件溯源對應一覽

| 動作 | 前端事件寫入 | 後端重播對應 |
|---|---|---|
| SP 分配 | `SP_ALLOCATE`（`kpi-dashboard.html:1217`） | `kpi-core.js:504-515,536` |
| 學招 | `MOVE_LEARN` | 由 `learnedMoves` 重算 |
| 升招 | `MOVE_UPGRADE` | 同上 |
| 裝招/卸招 | `MOVE_EQUIP` | `equippedMoves` 重算 |
| 重製樹 | `SKILL_RESET`（`kpi-dashboard.html:1247`） | 歸零 `learnedMoves` + 退 SP |
| TM 購買/消耗 | note 內嵌 `TM學習器:xxx`、`消耗N個TM學習器` | `kpi-core.js:403-404,419` |
| 進化 | 進化事件 note | `kpi-core.js:504-515` 授 SP |

> 前端派對：`recalculateStudentState` 是兩端唯一信任的真實來源（`index.js:22`），事件寫入後 Firestore `onKpiEventWritten`（`index.js:60`）觸發後端重播並覆寫快照。**招式狀態的前後端一致性因此由重播保證**。

## 7. 關鍵結論

1. 本系統是**非典型寶可夢**：對戰攜帶上限為 **6 招**（非原作的 4 招），且 TM 招與技能樹招可疊加。
2. 招式深度（SP）與招式廣度（階層 T1–T5）都由「升級＋進化」雙軌解鎖，形成明確成長曲線。
3. **兩套招式系統共存**：
   - 「主動學習」（技能樹 + TM）有完整的事件溯源，跨裝置/重載不遺失；
   - 「被動配招」（種族池/專屬招）純由等級與能力值即時計算，僅服務未自訂的寶可夢與敵方。
4. TM 學習器是**有價消耗品**（150 金幣、限第三階段、每寵 4 招上限），屬於明確的資源管理設計而非免費機制。
